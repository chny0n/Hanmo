## 2. 학생 사용자 흐름

1. `/degree-rescue/`에서는 **전공별 중요공지**와 **강의 전망**을 먼저 선택한다.
2. `/degree-rescue/academic-timeline.html`에서 캠퍼스·주전공(선택적으로 이중전공)을 입력한다. 학번과 성적표는 요구하지 않는다.
3. `importantNotices`는 학생이 명시적으로 선택한 전공과 자료의 검증 상태를 이용한다. 확인된 마감 고정 영역(최대 2건)과 단순 참고 후보 영역을 분리한다.
4. 각 공지의 '근거 주석'에서 원문/게시목록 링크, 판본, 게시일, 자료 검수 여부 및 적용 범위의 확인 가능성을 직접 점검한다.
5. 나머지 학사일정 목록·개인 메모·14개 졸업 체크리스트는 선택 기능이며, 학교 공식 자격/졸업사정의 대체가 아니다.
6. 강의 개설 전망은 '관측 n개 중 k개 개설'을 보여주되 수치 확률이나 공식 개설 확정으로 표기하지 않는다. 입력 JSON은 개발자용 진단으로 분리한다.

## 3. 의도적으로 보류하거나 축소한 기능

- **졸업 위험 진단·이중전공 변경 What-if·교환학생 자격 점검:** 관련 이수 계산·FAQ 공통 코어는 유지하되 교환학생 준비 검사 및 What-if 화면 뷰모델은 삭제했다. 공식 규정·학생 과거 이수 및 현재 수강내역을 신뢰 가능한 방법으로 *일괄 가져오고 검증*하는 기능이 없으므로 현재의 일반 학생용 대표 기능/정답으로 광고하지 않는다.
- **학칙 개정 영향 분석:** 판본 보존과 서로 다른 입학년도에 적용되는 RulePack 선택은 안전상 유지하되, 학생용 핵심 홍보 기능에서는 내린다. 비소급 적용 여부를 대학별·학번별 문서 없이 일반화하지 않는다.
- **독립 시간표 편집기:** 개발하지 않는다. 기존 시간표 서비스의 생성/편집 기능을 복제하지 않으며, 수강계획의 충돌·학점·선수요건 검사 코어는 내부 보조 기능으로 유지한다.
- **WIS 강의 HTML/CSV 로컬 불러오기:** 사용자가 파일을 제공할 수 있으나 졸업/학적 데이터의 자동 대량 취득을 뜻하지 않는다. 개인 원장 파일 수집/학교 인증·SSO 우회는 금지한다.

## 4. 신뢰 불변 조건

- `SOURCE_REVIEWED`라는 JSON **자기 선언**만으로 승인하지 않는다. 운영자 검수자가 제공한 **동일한 메모리 객체 참조**가 있어야만 검수된 상태가 된다.
- 현재 시제품은 신뢰된 운영 검수 로더를 배포하지 않으므로, 기본 제목 목록과 사용자 업로드에서 **검수된 마감 0건**이 정상이다. 참고 제목에 D-day/확정일을 생성하지 않는다.
- `appliesTo=NO`인 공지는 제외. 데이터가 없으면 `UNKNOWN`/검토 목록으로. 전공 선택만으로 본인 대상 또는 졸업시험 의무를 확정하지 않는다.
- 코드와 테스트는 `degree-rescue/` 아래에만. 기존 한모 `index.html`, `html/`, `js/`, `css/`, `img/`, `CNAME` 변경 0건.
- Supabase는 3차 설계·운영 인수 이후 실제 구축·연동·검증 대상. 이번 PR에 DB/SSO/로그인/크롤러/비밀키를 추가하지 않는다.
- HUFS One AI에서 이식된 순수 계산 코어·공개 학사자료의 저작권·재배포 권한과 GPL-3.0 호환성은 여전히 **병합 차단 게이트**다. 비실행 원본 아카이브 235개는 PR HEAD에서 삭제했지만 **과거 Git 커밋 이력에서는 계속 조회될 수 있다**.
