## 1. 두 정보처 직원의 설명과 운영자 해석

- **정보처 2026-11-23 이메일:** [서면 원문](sources/2026-11-23-hufs-information-office-reply.txt)은 **명시적 금지 항목**, **자동 수집의 수치/기간 제한**, **비공식 표시와 공식 원문 안내**를 포함합니다. 또한 마지막에 '위에 적지 않은 이용은 허용하지 않습니다'라는 포괄 조항이 있습니다.
- **운영자 결정:** **① 서면에서 명시적으로 금지한 이용은 금지, ② 자동 수집은 서면 조건을 모두 적용, ③ 서면에서 개별적으로 금지하지 않은 로그인 없는 공개자료의 사용·가공·검색·분석은 대면 설명에 따른 내부 운영 해석으로 진행**합니다. 추가 문의는 당분간 하지 않습니다. 독립적으로 구현한 알고리즘 및 합성 테스트에만 한정하는 이전 방침은 여기서 수정합니다.
- **충돌의 투명한 기록:** ③은 이메일의 '열거 외 이용 불허' 문구와 **해석 충돌** 가능성이 있습니다. 따라서 한모의 자체 위험 수용 판단일 뿐 **학교가 이를 공식적으로 승인했다거나 이메일의 포괄 조항이 무효라고 단정하지 않습니다.** 요청/정책 변경이 있으면 대상 자료의 이용을 즉시 중단합니다.

**공통 조건:** 각 필드에 공개 원문 URL·관측/확인일·필드 분류(명시 금지 / 공개 가공 후보 / 불확실)·가공 방식·개인정보 검사·정정/철회 여부·최종 검수자를 기록합니다. **명시 금지 항목은 무조건 차단**하고, 금지 용어에 해당하는지 불분명한 필드는 검수 완료 전 학생 화면에 노출하지 않습니다. 운영자 해석을 권리 증명/학교 허가로 저장하지 않습니다. 실제 공개에는 정확성·캐시·수집 조건·철회 가능성에 대한 독립 QA가 필요합니다.

**제품 우선순위:** PC 전용 기능 차별화(공지 정밀 검색, 과거 개설 분석, 공식 일정의 다중 출처 비교, 문의처 정밀 탐색)이며 개인 메모·알림 중심 UX는 우선하지 않습니다. 검색의 포괄성은 학교의 엄격한 수집 한도에 따라 제한될 수 있습니다.

## 3. 자동 수집 조건(서면 그대로 적용)

실제 학교 크롤러/스케줄러는 **미구현**, `data/academic-source-config.json`은 **`mode: disabled`**입니다. 이 의사결정은 설정 변경·실행 승인이나 수집 속도 상향을 뜻하지 않습니다.

- 로그인 없는 공개 화면에 보이는 URL만. 내부/비노출 API·SSO/계정·인증 우회 없음
- 학사공지 **1일 1회 이하, 첫 목록 페이지 및 신규 공지 상세만**; 강의시간표 **학기당 2회 이하**
- 요청 **10초 이상 간격**, 동시 **1개**, 실행당 **50건 이내**(여러 실행자/호스트 합산 관리)
- 수강신청·수강정정 기간 **전체 및 시작 전/종료 후 각 1일** 중단; 금지기간 전체를 확인하지 못하면 수집 시작 안 함
- 오류 응답/접속 제한 시 **당일 즉시 중단·재시도 금지**, User-Agent에 서비스명과 운영자 연락처 표기
- 학교 과부하·정책 변경·차단 시 수집과 해당 자료 공개 즉시 정지. 실제 구동은 [#66](https://github.com/ot4562-glitch/Hanmo_develop/issues/66) 합성/실환경 검증 및 [#126](https://github.com/ot4562-glitch/Hanmo_develop/issues/126) 긴급 철회 인수 뒤 별도 운영 판단

## 4. 중단 트리거

학교/권리자의 중단·삭제 요청, 정보 이용 조건 변경/철회, 오류·접속 제한·서버 부하, 개인정보나 서면 금지 필드 혼입, 허위/오래된 학사 정보, 출처 불일치·공식 서비스 오인 등이 확인되면 **우선 수집·해당 자료 노출을 차단**하고 원인 검토를 합니다. 학교 서버 오류가 난 날에는 다시 시도하지 않습니다.

## 5. 긴급 철회 런북 — '언제든 내리기'는 검증해야 함

1. **수집 중지:** 모든 스케줄/작업/요청 경로를 전역 OFF로 전환, 재시작·다중 인스턴스에서도 유지. 네트워크 경로 우회·오류 당일 재시도 없음
2. **학생 노출 중지:** 정적 스냅샷/JSON·Supabase 공개 뷰/API와 검색 인덱스에서 대상 자료 철회. 학생 화면은 `NOT_CONNECTED`/`INVALID`로 안전하게 전환. 단순히 설정 `mode: disabled`만 바꾸면 이미 배포된 파일은 남을 수 있음
3. **배포/캐시 정리:** GitHub Pages·다른 호스팅·이전 릴리스/아티팩트·CDN/브라우저 캐시·검색 엔진 색인·구형 백업/롤백 경로까지 확인. 급하면 해당 공개 호스팅을 우선 중지
4. **재노출 검사:** 익명 새 세션과 직접 파일 URL, 캐시/미리보기/이전판 및 Windows PC 브라우저에서 공개 자료가 사라졌는지 확인
5. **처리 기록:** 감지 시각(KST), 문제 출처/필드·공개 범위, 변경 SHA/배포 판본, 조치 담당·증거를 기록하되 원문/개인정보/학교 직원 신원 등은 불필요하게 남기지 않음
6. **재개 별도 심사:** 철회된 판본의 자동 복원·구형 빌드 롤백 금지. 운영자+독립 검수자가 필드·출처·수집 예산·정책과 기술적 재노출 방지를 확인한 경우에만 재개 여부 결정

**현황:** 아직 실제 학교 자료 수집·Supabase 실DB·공개 데이터 연결은 없으며, 통합 킬 스위치/캐시·배포 철회 자동화와 훈련도 **미구현·미검증**입니다. [#126](https://github.com/ot4562-glitch/Hanmo_develop/issues/126)이 완료되기 전 '언제든 내릴 수 있다'고 단정하지 않습니다.

## 6. 책임·인계

- **운영 범위·철회 책임:** `ot4562-glitch`; 두 직원과의 대면 설명 내용은 운영자 진술로 기록하며 학교 기관 차원의 확정된 사용권이라고 주장하지 않음
- **데이터/선택적 Supabase:** 김채윤(`qamarrchae`); 2차 [#71](https://github.com/ot4562-glitch/Hanmo_develop/issues/71) 이후 별도 Free 프로젝트 직접 실습, RLS/공개 필드 검증/백업·철회. 그전 실데이터 연결 OFF
- **검색·학생 UI:** 이의상(`uisang2004-maker`) 및 소유자. 금지 필드 누출·공식 오인·오류·PC 접근성 검증
- **최종 인수:** 완성 후 원개발자 `dlacked`에게 대면/서면의 차이, 운영자의 해석 책임, 자료 철회 기술과 제한사항을 포함해 실제 수락받음([#125](https://github.com/ot4562-glitch/Hanmo_develop/issues/125))

**공개 저장소 주의:** `docs/` 또한 공개입니다. 담당자의 비공개 발언 전문·신원·사적 연락처·서비스 키 등을 추가하지 않습니다.
