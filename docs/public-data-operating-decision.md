# 공개 학사정보 기능 개발 결정 · 운영 중단 및 철회 절차

> **운영자 의사결정 기록(2026-11-23) / GitHub 공개 저장소에 올라가는 개발 문서.** 이 문서는 한모 내부의 개발 우선순위와 사고 대응 절차를 정한 것이며, 한국외대의 공식 승인서·제휴·이용 허락 확대 증빙이 아닙니다. 구체적인 학교 담당자의 신원, 비공개 대화 내용 또는 민감한 운영 자격증명을 여기에 추가하지 않습니다.

## 1. 경위와 결정

- **운영자 전달 대면 설명:** 상위 담당자에게서 '로그인 없이 공개된 학교 자료는 서버에 무리가 없는 선에서 활용', '학교가 데이터 파일/API를 직접 제공하지는 않음', '독립된 비공식 서비스임을 분명히 표시'라는 취지의 설명을 들었다고 운영자가 보고했습니다. 구두 설명의 원문·직권 범위·최종 적용 조건은 문서로 검증된 것이 아닙니다.
- **2026-11-23 정보처 서면:** [수정 없는 원문](sources/2026-11-23-hufs-information-office-reply.txt)은 공개 공지·강의자료의 제한적 이용을 인정하면서도 교수명·수강 관련 정보 제외, 공지 본문·첨부 재게시 금지, 학칙·졸업요건/학교 대행 FAQ 금지, 수집 빈도·요청 간격·기간 제한, **열거 외 이용 불허**를 명시합니다. 학교의 인정·보증·제휴도 아닙니다.
- **운영자 최신 결정:** 반복적인 정보처 문의는 당분간 하지 않습니다. 대신 **공개정보 검색·분석·일정 통합·문의 경로 탐색 기능의 기술 설계·합성 데이터 구현을 폭넓게 허용**하고, 자료 이용·배포 가능성은 서면 조건과 분리합니다. 구두 설명을 이유로 서면의 명시적 금지나 제한을 임의로 해제하지 않습니다.
- 서비스는 PC 웹 전용이며 학교 시스템에 로그인하지 않습니다. 원개발자와 학교 관계를 학교 공식 서비스로 표현하지 않습니다.

**해석 원칙:** 공개 페이지에 보인다는 사실과 재게시·구조화·원본 보존·자동수집 허락은 동의어가 아닙니다. '추후 요구가 있으면 내리겠다'는 **사후 복구 계획**이지 현재 금지된 사용을 허용으로 바꾸는 수단이 아닙니다. 추가 서면 확인을 새 작업의 필수 조건으로 만들지는 않되, 확인되지 않은 **실제 자료의 해당 사용만 계속 OFF**로 둡니다.

## 3. 자동 수집·서비스 접근 기본 경계

실제 학교 크롤러는 현재 **존재하지 않으며**, `data/academic-source-config.json`은 `mode: disabled`입니다. 새 코드 작성만으로 수집이 시작되거나 학교 자료가 발행되지는 않습니다. 향후 실행 전에 다음 게이트를 프로그램으로 강제합니다.

- 공개 화면에 노출된 로그인 불필요 URL만 이용하며 비노출/내부 API, 인증 우회, 학교 계정이나 개인 자료 접근 금지
- 공지 **하루 1회 이하(첫 목록+신규 공지 상세만)**, 강의시간표 **학기당 2회 이하**
- 요청 간 **최소 10초**, 동시 요청 **1개**, 배치 **최대 50개**
- 수강신청/정정 **기간 전체 및 시작 전 1일·종료 후 1일** 자동 수집 금지, 다른 금지 일정을 확인 못 하면 실행 금지
- 4xx/5xx·접근 제한 등 오류를 만나면 **즉시 중단 후 해당 날짜 재시도 금지**, 운영자 식별 가능한 User-Agent, 전역 예산/잠금 기록
- 자료별 금지 필드 제거와 공개권한·정정/철회·검수, 개인/교수정보·공지 본문·첨부 제외, 비공식 안내와 공식 원문 링크
- 전역 수집 OFF·공개 스냅샷 OFF·안전한 정적 화면 전환 및 실데이터 미수집 테스트를 출시 게이트로 적용

수집 제한 상세는 [아키텍처 §0.1](architecture.md) 및 [#66](https://github.com/ot4562-glitch/Hanmo_develop/issues/66)을 기준으로 합니다. 문서에 있는 계획은 실제 구현/검증이 아닙니다.

## 4. 즉시 중단 트리거

학교나 자료권리자의 삭제·접근 중지 요청, 정책 변경/철회, 학교 서버 오류·차단·부하 증가, 개인정보/비공개 자료 혼입, 출처/권리 불명, 잘못된 공개 정보 또는 공식 서비스 오인, 데이터 검수 실패가 발견되면 **운영자 판단을 기다려 사용을 계속하지 않고 먼저 해당 데이터 경로를 차단**합니다. 특히 서버 오류는 그날 재시도하지 않습니다.

## 5. 긴급 철회 런북 — 수집 OFF만으로 완료 아님

1. **정지:** 수집 스케줄·작업·HTTP 네트워크 진입점을 멈추고 재시작·다중 실행에서도 잠금이 유지되게 함. 장애·요청을 새 수집기로 우회하지 않음.
2. **노출 중단:** 공개 스냅샷/정적 JSON/DB 공개 뷰 및 읽기 API를 즉시 차단하고, 학생 UI는 `NOT_CONNECTED` 또는 `INVALID`과 공식 원문 안내로 전환. 단순히 브라우저 설정 `mode: disabled`로 바꿨다고 이미 게시된 정적 파일이 삭제된 것은 아님.
3. **배포 산출물 제거:** GitHub Pages 미리보기/운영 배포물, 이전 배포 릴리스/아티팩트/백업, CDN·브라우저 캐시·검색 인덱스 및 구형 롤백 파일을 점검해 철회 자료가 다시 공개되지 않도록 함. 급한 경우 해당 Pages/호스팅 공개 자체를 끊음.
4. **확인:** 익명 새 세션·PC 브라우저·직접 파일 URL·캐시 재검증에서 철회 데이터가 보이지 않는지 확인. 관리자 권한·서비스 키·읽기 권한/재노출 차단도 확인.
5. **기록:** 최초 인지 시각(KST), 출처, 영향을 받는 자료 범위, 실행한 차단, 검증한 URL·빌드 SHA, 담당자, 학교 또는 권리자와의 연락 요청 유무를 남기되 불필요한 개인정보·원문은 기록하지 않음.
6. **재개 심사:** 동일 출처의 재활성화·오염된 이전 빌드로의 복구는 자동으로 하지 않음. 운영자와 독립 자료 검수자가 구체적 근거·수집 게이트·실행/브라우저 시험을 다시 확인한 경우에만 재개 여부 결정.

**현행 구현 상태:** 긴급 수집·공개 차단의 **통합 구현/테스트는 아직 없음**. 학생용 실자료 연결 자체도 OFF입니다. [#126](https://github.com/ot4562-glitch/Hanmo_develop/issues/126)을 통해 기술적 킬 스위치와 정적 배포/캐시/롤백까지 실증해야 하며, 체크리스트 작성만으로 중단 가능성을 검증했다고 주장하지 않습니다.

## 6. 책임과 인계

- **저장소 소유자/최종 운영 결정:** `ot4562-glitch`. 데이터 범위/출시 승인, 학교 요청 수신 시 서비스 접근 중단, 복구 판정.
- **데이터·선택적 Supabase 책임:** 김채윤(`qamarrchae`). 2차 #71 실제 QA 이후 3차에서 별도 Free 실습, RLS/백업/철회 검증. 운영 승인 전 프로젝트 생성·실자료 업로드 없음.
- **검색/학생 UI:** 이의상(`uisang2004-maker`) 및 소유자 공동. 학교 공식 서비스 오인·금지 데이터 노출·외부 원문 링크 품질 테스트.
- **최종 수신자:** 전체 완료 후 원개발자 `dlacked`에게 운영 중단 수단과 미확정 이용 범위를 포함해 설명하고, 실제 수락 여부는 [#125](https://github.com/ot4562-glitch/Hanmo_develop/issues/125)에서 별도 확인.

**공개 저장소 유의:** 이 문서는 `docs/` 아래 있더라도 GitHub 공개 저장소 사용자에게 읽힙니다. 사람의 비공개 발언/대면 담당자 특정 정보, 서비스 키, 위기 대응 연락처의 비공개 정보는 여기에 저장하지 않습니다.
