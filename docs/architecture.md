## 0. 2026-11-23 서면의 명시적 금지·수집 조건 및 대면 가공 설명의 운영 해석

[공개자료 운영 방침](public-data-operating-decision.md)이 자료 정책의 정본입니다. [정보처 서면 회신 원문](sources/2026-11-23-hufs-information-office-reply.txt)과 운영자 전달 대면 안내를 함께 기록하되 학교의 공식 승인으로 해석하지 않습니다. 서면 명시 금지·수집 제한·비공식 표시·철회 조건은 기존 학업 기능 설계보다 우선합니다. 학교 자료는 미연결이며 학칙/졸업요건·FAQ 답변·교수명·수강 관련 정보·개인 학적·학교 계정은 학생 서비스에서 제외합니다. 공지 메타데이터·공개 개설 관측·일정은 필드별 권리·검수·철회 조건을 충족할 때만 공개 후보가 됩니다.

### 0.1 자동 수집 계약 · 위반 시 실패 폐쇄

구체적인 수집 제한·오류 차단·중단 절차는 [운영 방침 §3](public-data-operating-decision.md)과 [수집 범위](academic-data-collection-scope.md)를 따릅니다. 수집 금지 일정의 단일 정의는 [data/collection-blackouts.json](../data/collection-blackouts.json)이며 2026년 동계 일정은 부분 검증 상태입니다. 신청/정정 기간의 하루 전부터 하루 후까지 KST 날짜 전체를 차단하고 다른 일정 미확인·자료 연결 OFF·예산 미구현 시 실행을 불허합니다. [scripts/collection-window.mjs](../scripts/collection-window.mjs)가 검사하며 npm run collection:status는 조회, npm run collection:gate는 실제 시각으로 실행 가능 여부를 강제합니다. 실제 크롤러와 전역 요청 예산은 #66에서 별도 검증하며 현재 학교 요청을 실행하지 않습니다.

### 0.2 금지 기능·기존 구현·배포 차단

**웹 1차 정리 반영:** 졸업 준비 `html/academic-progress.html`과 학사 FAQ `html/academic-faq.html`, 전용 CSS·FAQ JS, 학교 로고 `img/hufs_logo.png`는 [웹 정리 커밋](https://github.com/ot4562-glitch/Hanmo_develop/commit/2712bd939502a31755fd21026ac96fe81650c552)에서 삭제했습니다. 메뉴·사이트맵·빌드·테스트도 수정했습니다. **학교 학칙/졸업요건·FAQ 계산 및 근거형 답변의 순수 코어와 옛 데이터 소스 계약은 코드에 남을 수 있지만 운영 기능은 아닙니다.** 학교 자료 연결 `mode: disabled`를 유지하고 웹 디자인·접근성/실기기 검수는 별도 완료 게이트입니다.

학교 문양을 사용하던 기존 홈·상단바·이미지·파비콘·SVG·메타정보와 실제 수강신청을 연상시키는 화면은 **별도 수정 및 브라우저 QA 대상**입니다. 기존 UI 동결 정책은 새 서면 금지사항을 보존할 근거가 아니므로 관련 변경을 우선하되, 원본 동작·실기기 회귀·디자인 구별을 확인합니다. **2026-11-23 웹 1차 정리로 금지된 페이지·학교 로고 파일 제거와 비공식 고지를 반영했습니다. 그러나 디자인 전수/Windows 실기기 QA, 원본 운영 도메인 공개·학교의 서비스 인정은 완료되지 않았습니다.** `data/academic-source-config.json`의 `mode: disabled`를 유지하고, 금지된 필드가 포함된 기존 Supabase Draft #93·공개 payload는 수정·재설계 전 활성화하지 않습니다.

### 0.3 운영자 최종 해석(2026-11-23) · 공개자료 가공 이용과 즉시 철회

운영자의 대면 안내 기반 해석·서면의 열거 외 이용 불허 문구와의 충돌, 필드별 판단 및 긴급 철회는 [공개자료 운영 방침](public-data-operating-decision.md)에 기록합니다. 학생 기능은 공지 정밀검색·공개 개설 관측 및 비식별 추세, 월간 달력 순으로 검토합니다. 독립 문의처·변경 공지 전용 필터·정정 전후 비교는 제외합니다. 실제 연결·수집·통합 킬 스위치는 미구현입니다(#41·#66·#126·#127).

### 0.4 데이터 범위 양방향 변경을 고려한 데이터·배포 아키텍처(목표)

- **정책 원장:** 각 안내에 `sourceKind`(직원 서면·운영자 전달 대면·확인된 기관 정책), 확인일·적용 판본·공식성 확인 여부·데이터 필드별 사용 판단과 변경 이력을 연결합니다. **현 상태는 직원 안내 기반 잠정 정책**입니다. 향후 학교 전체 정책을 새로 확인하면 다른 증거 등급으로 기록합니다.
- **축소 경로(우선):** 변경/중단 요청 즉시 해당 출처·필드 수집 및 공개를 OFF → 정적 JSON/Supabase/API/검색 색인 및 Pages·캐시·구판 경로 철회 → 익명 검증. [#126](https://github.com/ot4562-glitch/Hanmo_develop/issues/126)의 킬 스위치·롤백 방지 완료 전 자동화가 구현됐다고 간주하지 않습니다.
- **확대 경로(별도 검수):** 새로운 근거를 확인한 뒤 `scopePolicyVersion`을 갱신하고 필드별 금지·개인정보·학교 공식 오인·출처/정정·수집 예산을 재검수해 새로운 DTO/스냅샷 후보를 승인합니다. **예전 잠정 안내의 존재만으로 자동 확대하지 않고**, 제한된 수집 횟수를 우회하지 않습니다.
- **변경 테스트:** 금지 필드 추가/제거, 수집 상한 변경, 철회 후 구판 캐시 복구, 확대 후에도 오래된 금지 필드가 재노출되지 않는지 합성 회귀. 운영 담당·최종 인계는 #41·#66·#73·#125·#126에 추적합니다. 실제 정책 버전 레지스트리/자동 무효화 기능은 아직 **미구현**입니다.

사용자가 직접 진단 시작을 눌렀을 때만 측정합니다. 브라우저에서는 `requestAnimationFrame` 예열 0.5초+실측 약 3초, 프레임 간격 중앙값/P95, `max(50ms, 중앙값×3)` 이상 끊김, 가능할 때 `PerformanceObserver` 긴 작업(50ms+), 타이머 지연 P95를 관측합니다. `hardwareConcurrency`·`deviceMemory`·`NetworkInformation`은 브라우저 지원 시 추정치만 표시합니다.

한모 동출처에서만 HEAD 5회와 `data/network-probe.txt`의 GET 2회를 실행합니다. 요청마다 캐시 우회와 5초 타임아웃을 적용하고 리디렉션을 거부합니다. Resource Timing의 요청 전체 시간으로 HTTP 응답 중앙값을 구하고, 연속한 유효 요청 차이의 중앙값을 지터로 보고합니다. 다운로드는 약 262KB 시험 파일의 완전한 수신을 확인한 뒤 전송 인코딩이 반영된 본문 크기를 요청 전체 시간으로 나눕니다. 브라우저 캐시, 서비스 워커 개입, 전송을 확인할 수 없는 표본은 실패와 구분해 집계합니다. 사용자가 취소하거나 탭이 숨겨지면 결과를 확정하지 않습니다. CDN 관측은 회선의 공인 Mbps나 학교 수강신청 성능을 나타내지 않습니다.

진단 결과 아래에는 실제로 관측된 이상에 해당하는 권장 조치만 표시합니다. 화면 끊김·갱신 지연은 화면 설정, 긴 작업·타이머 지연은 브라우저 부하, 반복 요청 실패는 한모 연결 확인과 재검사를 안내합니다. 중복 조치는 묶고 단발 실패·표본 제외는 측정 제한으로 구분합니다. 미지원·미실시 지표 및 CPU·메모리·네트워크 유형의 추정치만으로 새 이상 판정을 하지 않습니다. 정상 결과에는 불필요한 조치 목록을 표시하지 않으며, 재검사 시 이전 안내를 교체합니다.

## 5. 전략 실험: 신청 순서 추천

사용자가 한 번의 선착순 회차에서 신청할 가상 과목 2~8개를 입력합니다. 과목명, 중요 순위, 여석으로 입력하는 정원(1~300), 본인 제외 경쟁자 수(0~200)를 받습니다. 추천은 브라우저에서 계산합니다.

추천은 개시 직후의 선착순 구간을 대상으로 하며 취소와 증원을 고려하지 않습니다. 이전 합성 엔진의 다과목 순차 신청과 응답 후 다음 요청을 보내는 구조를 신청 차례 단위로 적용합니다.

- 경쟁자가 신청할 과목 수 `m`을 1~8개로 비교합니다. 해당 과목을 고려하는 경쟁자 `R`명의 신청 차례가 고르게 분포한다고 두면, `q`차례까지의 누적 요청 수는 `floor(R × q / m)`입니다. 시작 여석 `C`에 도달하는 마감 차례는 `ceil(C × m / R)`이며, `R < C`이면 이 조건에서 마감되지 않습니다.
- 내 첫 요청 앞에 경쟁자의 첫 차례가 없거나 이미 한 차례 처리된 경우를 비교합니다. 내 연속 요청 사이에는 경쟁자가 1~`m`차례 진행하는 경우를 모두 비교합니다. 내 `s`번째 요청 직전 상대 차례는 `첫 요청 직전 차례 + (s − 1) × 요청 사이 차례 수`입니다. 정원에 닿은 차례와 같으면 이미 마감된 것으로 계산합니다. 이 가정은 상대 처리 순서와 응답 대기의 영향을 비교하기 위한 것이며, 경쟁자의 실제 과목 선호·인터넷 지연·서버 처리율은 측정하지 않습니다.
- 각 조건에서 확보 가능한 최대 과목 수를 마감이 빠른 순으로 빈 신청 자리에 배치해 계산합니다. 가능한 신청 순서 최대 40,320개에서 조건별 최대 과목 수 대비 놓치는 과목 수가 가장 작은 최악의 차이를 고릅니다. 동률이면 중요 순위가 뒤집힌 과목 쌍이 적은 순서, 다시 동률이면 앞자리부터 중요 순위가 높은 순서를 고릅니다. 각 조건에는 발생 확률을 부여하지 않습니다.

예를 들어 1석에 경쟁자 200명인 과목과 20석에 19명인 과목을 신청한다면, 첫 대기 차례를 놓치면 마감될 수 있는 1석 과목을 먼저 추천합니다. 자리당 경쟁자 수가 비슷해 같은 차례에 마감되는 과목들은 중요 순위대로 배치합니다.

정원과 경쟁자 수가 같아도 경쟁자가 언제 어떤 과목에 신청하는지에 따라 결과가 달라집니다. Siefken은 실제 등록 지연을 분석했고, 거래 기록 연구는 시각이 있는 신청·대기·취소 데이터를 사용했습니다. Budish와 Cantillon은 하버드 경영대학원의 배정 방식과 그에 따른 전략 행동을 분석했습니다. 연구의 자료 단위와 배정 방법이 한모 입력과 다르므로 한국외대의 실제 성공률을 이 자료로 추정할 수 없습니다. [등록 지연 연구](https://files.eric.ed.gov/fulltext/EJ1142349.pdf) · [수강신청 거래 기록 연구](https://educationaldatamining.org/EDM2023/proceedings/2023.EDM-short-papers.39/index.html) · [다과목 배정 연구](https://doi.org/10.1257/aer.102.5.2237)

기존 합성 몬테카를로 엔진과 검증은 연구 코드로 보관합니다. 공개 빌드에서는 추천 모듈만 제공하며, 과거 밀리초 단위 설정과 반응 프로필은 연구 코드에 남아 있습니다.

## 6. 기존 모의수강신청 계약 (2차)

- BASIC/TIME/SELECT의 핵심 연습/결과 흐름을 원작 기준으로 보호.
- `practice.html`과 `selectZone.html`의 기존 좌측 정보 영역에 동일한 내정보의 입학년도·캠퍼스·전공·이중전공/부전공을 로컬 저장값에서 읽어 표시합니다. 미입력 항목은 미입력으로 남기고 학번 전체·성명·수강학년·가능학점은 생성하지 않습니다. 학교 로그인이나 학적 조회가 아니며 연습 타이머·버튼·신청 로직은 변경하지 않습니다. 양쪽 파란 정보 영역 하단에는 사용자 승인된 노란색·검정 경고 표지(모의수강신청 중 / 실제 수강신청 시스템이 아니에요)를 상시 표시하며, 항목 사이 여백과 행간을 줄여 일반적인 내정보는 기존 218px 높이 안에서 스크롤 없이 표시합니다. 매우 긴 전공명은 숨기거나 내부 스크롤하지 않고 정보 영역 높이를 필요한 만큼 늘립니다.
- 사용자가 제공한 겨울계절학기 참고 화면의 **영역 규격만** 적용합니다. 신청·신청내역 영역의 너비는 우측 본문의 95.3%, 상단 목표 높이는 뷰포트의 46%, 하단은 24%(100~260px)로 제한합니다. 두 영역에는 별도의 눈에 보이는 외곽선을 추가하지 않고 크기만 제한합니다. 기존 표의 셀·헤더 테두리는 유지하고 두 영역은 독립적으로 스크롤하며 작은 뷰포트에서는 콘텐츠를 읽을 수 있도록 축소 또는 내부 스크롤합니다. 검색 전후 좌표와 기존 열/가상 과목/버튼/색상은 유지합니다.
- `RECONNECT`: BASIC에서 선택적으로 가상 404를 1회 띄우고 사용자의 **실제 브라우저 새로고침**으로 복구. 뒤로가기/학교 실서버 복구와 다름.
- `CAPACITY`: BASIC의 가상 한 과목을 마감 처리하고 **합성** 전공/교양/기초 후보 검색 연습. 학교 정원·실수강·시간 충돌 데이터와 무관.
- 두 돌발상황 선택은 각각 기본 OFF, 독립된 로컬/세션 설정. 강의 신청 대기 기본 예, **페이지 접속 대기 기본 아니오**. 접속 대기 ON이고 404 복구가 필요한 경우 복구 뒤 적용.
- 원본 두 칸 예/아니오 인터랙션, Enter 확인, 대기번호와 타이머/결과를 보호. 합성 도구 추가로 해당 저장 키/원본 라우팅 변경 금지.
- 사용자 승인 범위에서 신청 버튼은 Tab과 Enter로 조작할 수 있게 하고 과목별 접근 가능한 이름을 제공합니다. 결과는 손상된 저장 시간을 `0.000초`로 처리하며 합성 대기 차감 후 음수를 표시하지 않습니다.
- `html/result.html`의 **PNG 공유 버튼과 전용 모듈은 사용자 요청으로 제거**됐습니다. 남아 있는 모의신청 결과 텍스트와 ‘이어서 연습하기’는 유지.

## 7. 학사 정보·공지 검색·강의 개설 관측 (1차, 미연결)

- `학사 정보`는 공지/달력 탭 단일 URL. 공지 최소 메타 검색 입력은 실제 검수 데이터 전까지 비활성. 달력은 월간 공백+공식 원문 링크만 제공. 미연결·자료 없음·오프라인·검증 실패·연결의 상태를 구분하되 UI가 공식 날짜를 임의 확정하지 않습니다.
- `강의 검색`의 과목·개설 관측·비식별 전망은 조건부 제품 목표로 두되 **학교 제공 과거 원장/API가 없음**을 숨기지 않습니다. 현행 화면은 미연결. 교수명·정원/수강 상태 등 금지·불명확 필드는 공개 금지.
- `학교 문의처` 독립 메뉴/HTML/CSS/JS는 사용자 지시로 삭제, 관련 #59는 not_planned 종결. 학교를 대신한 문의 응답/FAQ를 구현하지 않습니다.
- 협업 PR의 최신 검토·검증 상태는 [미결 이슈](pending-issues.md)에서 관리하며 실제 학교 자료 연결 OFF를 유지합니다.
- 공지 자동 수집/재게시·일정 확정·학생별 자격 판단을 수행하지 않습니다. 세부 목표·권리·예산은 [최소 데이터 계획](focused-public-data-plan.md)과 #53·#44·#127.
