# #71·#72 Windows 실기기 인수 체크리스트

이 문서는 자동화 증거와 물리 입력 인수를 분리합니다. Windows hosted runner의 Chrome/Edge 자동화는 Windows 브라우저 회귀를 확인하지만 실제 PC·물리 키보드·NVDA·브라우저 200% 확대의 인수가 아닙니다.

## 최신 SHA 자동 검증

[Windows browser QA](https://github.com/ot4562-glitch/Hanmo_develop/actions/workflows/windows-browser-qa.yml)는 chrome/msedge를 각각 실행하며 OS·브라우저 버전·SHA·결과·캡처를 산출물에 남깁니다. 브라우저가 없거나 실패하면 Chromium으로 대체하지 않습니다. 기존 Linux Repository checks도 유지합니다.

## 실기기 준비

1. 검증할 커밋의 깨끗한 작업 디렉터리에서 Node 22, npm ci, npm run check를 실행합니다. 실제 학교 계정과 데이터는 사용하지 않고 브라우저 별도 테스트 프로필을 사용합니다.
2. npm run test:e2e 및 npx playwright test --config tests/playwright-feature.config.mjs를 설치된 Chrome/Edge에서 각각 실행할 수 있습니다. PowerShell에서 먼저 환경변수 HANMO_BROWSER_CHANNEL을 chrome 또는 msedge로 설정합니다.
3. npm run build 및 node scripts/serve-static.mjs로 로컬 QA 페이지(http://127.0.0.1:4173/index.html)를 엽니다. 학교 원문 링크 검증은 외부 요청 없이 링크 속성/새 탭 동작을 확인합니다.
4. 테스트 PC의 OS, 화면 실제 해상도/배율, 브라우저 버전, 실제 페이지 확대 100%와 200%, 검증자, 날짜, Git SHA를 기록합니다. Windows 실제 Chrome/Edge 각각 1280×720 및 1920×1080에서 100%/200%를 확인하며 일반 PC 1440×900도 확인합니다. NVDA Speech Viewer에서 낭독 결과를 기록합니다.

## #72 접근성·기기·삭제 UI

| 항목 | 실제로 확인할 내용 | 결과/증거 |
|---|---|---|
| 고지·브랜딩 | 모든 주요 화면의 비공식 고지·학교 원문 확인 안내, 공식 로고/오인 여부, 실제 확대 시 가림 | 미검증 |
| 키보드·NVDA | Tab/Shift+Tab/Enter, 도움말 i, 공지/달력 탭, 내정보, 대기·오류·빈 상태, 가상 신청/삭제/재수강 이름, 포커스 가시성·낭독 | 미검증 |
| 일반 PC | 1280×720 및 1440×900 모든 일반 화면과 진단 11개·등급 기준·전략 8과목 결과/버튼 표시; 허용된 목록/수식 외 스크롤 없음 | 미검증 |

| 개발자 소개 #138 | Chrome/Edge 실제 100%·200%: 이름·소속·역할의 줄바꿈 및 읽기, Tab/Enter로 뒤로 버튼, NVDA 낭독 확인. #71/#72와 같은 SHA·환경·캡처 사용 | 미검증 |
| 삭제 UI | 졸업·FAQ·독립 문의처·독립 달력·학교 마크의 직접 URL/사이트맵/검색 노출, PNG 공유 재유입 없음 | 미검증 |

증거는 합성 입력만 사용한 화면·이벤트 기록으로 제출합니다. 개인 프로필, 로그인 정보, 실제 학생 데이터는 첨부하지 않습니다. PASS/FAIL/미검증을 구분하고 실패가 있으면 단계·환경·SHA·캡처를 #71/#72와 연결합니다. 외부 검색 인덱스의 과거 캐시 및 NVDA 물리 인수는 자동 CI로 완료할 수 없습니다. #67 선행 조건은 #71 실제 인수 전까지 유지합니다.
