# 코드 주석 작성 지침

이 문서는 한모의 TypeScript·JavaScript·HTML·CSS·테스트 코드에서 유지보수를 위한 주석을 작성하고 수정할 때 적용합니다. 기능의 기준은 [현행 아키텍처](architecture.md), 작업·승인 절차는 [에이전트 운영 규칙](../agent.md)을 따릅니다.

## 기본 원칙

1. **설명 문장은 자연스러운 한국어로 작성합니다.** 기존 영어 주석과 JSDoc 설명도 같은 기준으로 옮깁니다. 단, 변수·함수·타입·API·파일 경로·상태값·오류 코드·JSDoc 태그(`@param`, `@returns`, `@throws` 등)는 원형을 유지합니다.
2. **무엇을 실행하는지보다 왜 그렇게 해야 하는지를 설명합니다.** 입력 신뢰 경계, 예외 처리 이유, 자료 출처, 시간대·단위, 과거 버전과의 호환성, 의도적인 제한, 변경 시 주의사항을 우선합니다.
3. 코드만 읽어도 알 수 있는 내용을 줄마다 반복하지 않습니다. 주석이 길거나 중복되면 핵심 근거를 한 곳에 남기고 나머지는 삭제·통합합니다.
4. 주석은 **현재 코드 동작과 일치**해야 합니다. 계획이나 미구현 동작을 완료된 기능처럼 서술하지 않으며, 실제 동작을 바꾼 경우 관련 주석과 테스트 설명도 함께 고칩니다.
5. 외부 라이선스·저작권 고지, 공식 원문 인용, 고정 프로토콜 문자열, 테스트 재현 명령은 의미와 형식을 보존합니다. 번역을 이유로 실행 코드·식별자·계약을 변경하지 않습니다.

## 위치와 형식

- **파일/모듈 첫머리:** 책임 범위, 주요 입력·출력, 부작용, 다른 모듈과의 경계를 설명할 필요가 있을 때만 작성합니다.
- **공개 함수·복잡한 계산:** JSDoc으로 목적·핵심 전제·반환값·오류 조건을 기록합니다. 매개변수 설명은 한국어로 쓰되 태그와 이름은 유지합니다.
- **복잡한 분기·보수적 실패 처리:** 조건식 자체를 되풀이하지 말고, 왜 `UNKNOWN`·`NEEDS_REVIEW`로 보류하는지, 어느 근거가 확정 판정을 허용하는지 설명합니다.
- **테스트:** 합성 자료 여부, 반례 의도, 사람이 계산한 기대값, 고정 시드 및 재현 명령을 기록합니다. 단순한 단언문 해설은 생략합니다.
- **HTML/CSS:** 접근성·기존 DOM 의존성·레이아웃 호환성처럼 코드만으로 파악하기 어려운 이유가 있을 때만 주석을 작성합니다.
- 생성된 번들이나 외부 라이브러리 파일은 주석을 직접 편집하지 않고 유지보수 **원본 소스**를 수정합니다.

## JSDoc 예시

```ts
/**
 * 승인된 근거가 없는 마감일은 확정된 학생용 D-day로 표시하지 않는다.
 * @param asOf - 시간대가 포함된 기준 시각
 * @param deadlineAt - 공식 확인된 학생 신청 마감 시각
 * @returns 표시 가능한 마감 정보 또는 검토 보류 상태
 */
```

JSDoc은 실제 인수·반환 계약과 일치하게 작성합니다. 예시를 그대로 복사해 실제로 존재하지 않는 매개변수나 검증 절차를 문서화하지 않습니다.

## 한모에서 반드시 구별할 사항

- **합성 모의수강신청**과 학교의 실제 수강신청·학점·학적 정보
- **과거 개설 횟수·예상 일정**과 공식 확정 개설·접수 기간
- **학생 입력·외부 JSON의 자체 선언**과 독립적으로 확인된 학교 원문·승인 상태
- **학과 내부 처리 마감**과 학생에게 적용되는 실제 신청 마감
- **미확인 자료(UNKNOWN)**와 공식 확인된 미개설·미충족·비적용 상태
- **브라우저 로컬 저장**과 학교 서버 또는 외부 서비스로의 전송

학교 학사자료의 수집·저장·재사용 권한은 **학교 회신과 별도 검토 전까지 확정된 것으로 주석에 쓰지 않습니다.** 자료의 출처 주소나 `SOURCE_REVIEWED` 문자열만으로 공식 승인됐다고 설명하지 않습니다.

## 수정 전 점검

- 같은 의미의 영어 주석이나 중복 설명이 남아 있지 않은가?
- 한국어 설명이 실제 로직·예외·타입·테스트 기대값과 일치하는가?
- 식별자·JSDoc 태그·API·문자열·동작·보안 및 개인정보 경계를 변경하지 않았는가?
- 주석만 고친 경우에도 변경 내역을 확인했고, 해당 단계에서 실행 가능한 검증을 수행하거나 미실행 사유를 명시했는가?
